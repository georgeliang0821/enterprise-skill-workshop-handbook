# 會議逐字稿整理 Skill(Meeting Notes Skill)

## ① 適用範圍 / 不適用時改用
- 適用:使用者提供一份會議逐字稿或會議紀錄全文,並要求產生摘要、決議、風險、或待辦事項——這四項只要使用者要求其中任何一項,都由這個 Skill 一次處理,不需要分別呼叫。
- 不適用:使用者只是「討論某個主題」、沒有提供實際逐字稿內容——這種情況不必勉強套用這個 Skill,直接對話回答就好。
- 不適用:使用者要的是看本週空檔、把未結事項排進去跟進 → 改用 `weekly-followup-planner`。
- 不適用:使用者要的是把會議內容拆解成專案任務結構(WBS) → 改用 `wbs-generator`。

## ② 需要的輸入
1. 會議逐字稿全文(必要)。可以是貼上的文字,也可以是檔案內容。
2. 會議日期(必要)。逐字稿裡的期限常是「這週五」「下週三」這種相對日期,沒有會議日期當基準,無法換算成實際日期,缺少時要先反問使用者。
3. (選)與會人員名單。沒有名單對照時,保留逐字稿原始代稱,不要自己編造人名。

> 逐字稿內容不完整(例如明顯被截斷)時,先跟使用者確認,不要憑殘缺內容硬生出摘要或待辦事項。

## ③ 步驟
1. 通讀全文,辨識這場會議在討論的主要議題(可能不只一個)。
2. 針對每個議題,萃取「目前狀態」,合併成一段精簡的專案進度摘要(不超過 3-4 句話)。
3. 掃描全文找出所有「明確被會議中的人拍板同意」的事項,列為 Decisions——注意:**只有真正拍板的才算決議,單純「討論中」「有人提議但沒共識」的不算**。
4. 掃描全文找出所有被明確提及、屬於「可能影響專案進度或合規的疑慮」的內容,列為 Risks——每一項風險要能對應到逐字稿裡具體的一段發言,不能是摘要者自己推論出來、逐字稿沒提到的風險。
5. 掃描全文找出所有「A 對 B 明確指派任務」或「某人主動承諾要做某件事」的語句(通常會伴隨「麻煩你」「你這邊負責」「我這週會…」這類語感)。
6. 對每一筆任務萃取:
   - **Owner**:負責人姓名(用逐字稿裡出現的實際名字,不要用職稱代替)
   - **Action**:具體要做的事(動詞+受詞,例如「PoC 架構設計」,不要只寫「跟進」這種空泛字眼)
   - **Due Date**:把逐字稿裡的相對日期,依②的會議日期換算成實際日期(YYYY-MM-DD)。如果逐字稿完全沒提到期限,標記為「未訂」,不要自己編一個日期。
   - **Priority**:依上下文語氣判斷(逐字稿裡有明確講「最優先」「不急」等字眼就依此判斷;完全沒有語氣線索的,一律標記為 Medium,不要自己過度推測成 High)。
7. 檢查是否有同一個人被指派多筆任務,分開列出,不要合併成一筆。
8. 依 ④ 的格式整理輸出。

## ④ 輸出格式
使用以下 Markdown 結構輸出,四個區塊都要有,即使某區塊內容是「無」也要明確寫出「無」而不是省略整個區塊:

```markdown
## Meeting Summary
<一段 3-4 句話的專案進度摘要>

## Decisions
1. <決議事項一>
2. <決議事項二>
...

## Risks
- <風險項目一>
- <風險項目二>
...

## Action Items
| Owner | Action | Due Date | Priority |
|---|---|---|---|
| <姓名> | <具體任務> | <YYYY-MM-DD 或「未訂」> | <High/Medium/Low> |
```

## ⑤ 品質自檢(產出後逐項確認,沒過就修再交)

**摘要類(Meeting Summary / Decisions / Risks)——風險是幻覺**
- [ ] 摘要只包含逐字稿裡真實出現的資訊,沒有推論、沒有幻覺內容。
- [ ] Decisions 裡的每一項,都能在逐字稿找到對應的「明確拍板」語句(例如「我們決議…」「那就這樣定案」),不是單純的討論或提議。
- [ ] Risks 裡的每一項,都能在逐字稿找到對應的具體發言,且用詞精簡(2-4 個字的風險標籤,例如「Token Cost」「Data Residency」),不要整句話塞進去。

**結構化類(Action Items)——風險是欄位錯誤**
- [ ] 每一筆的 Owner 都是逐字稿裡實際出現的姓名,不是職稱、不是猜測。
- [ ] 每一筆的 Action 是具體動作,不是空泛字眼(反例:「跟進」「處理一下」)。
- [ ] Due Date 若逐字稿有提到相對日期,已正確換算成實際日期;若沒提到,標記「未訂」而非自行捏造。
- [ ] Priority 沒有語氣線索時一律 Medium,不過度推測。
- [ ] 沒有把「討論中、還沒指派給特定人」的內容誤判成 action item。
- [ ] 同一人多筆任務有分開列出,沒有被合併。

**共通**
- [ ] 人名保留逐字稿原文寫法,沒有自己代換或猜測身分。
- [ ] 四個區塊都存在,內容為空時明確寫「無」。
