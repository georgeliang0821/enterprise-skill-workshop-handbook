# 會議逐字稿摘要 Skill(Meeting Summary Skill)

## ① 適用範圍 / 不適用時改用
- 適用:使用者提供一份會議逐字稿或會議紀錄全文,並要求產生摘要、決議、風險、或待辦事項——這四項只要使用者要求其中任何一項,都由這個 Skill 一次處理,不需要分別呼叫。
- 不適用:使用者只是「討論某個主題」、沒有提供實際逐字稿內容——那種情況屬於一般對話,不必勉強套用這個 Skill,直接對話回答就好。
- 不適用:使用者要的是看本週空檔、把未結事項排進去跟進 → 改用 `weekly-followup-planner`。

## ② 需要的輸入
1. 會議逐字稿全文(必要)。可以是貼上的文字,也可以是檔案內容。
2. 會議日期(必要)。逐字稿裡的期限常是「這週五」「下週三」這種相對日期,沒有會議日期當基準,無法換算成實際日期,缺少時要先反問使用者。
3. (選)與會人員名單。如果逐字稿裡的發言人是用代稱(如「主持人」「與談人A」),但沒有名單對照,輸出時保留原始代稱,不要自己編造人名。

> 逐字稿內容不完整(例如明顯被截斷)時,先跟使用者確認,不要憑殘缺內容硬生出摘要。

## ③ 步驟
1. 通讀全文,辨識這場會議在討論的主要議題(可能不只一個)。
2. 針對每個議題,萃取「目前狀態」,合併成一段精簡的專案進度摘要(不超過 3-4 句話)。
3. 掃描全文找出所有「明確被會議中的人拍板同意」的事項,列為 Decisions——注意:**只有真正拍板的才算決議,單純「討論中」「有人提議但沒共識」的不算**。
4. 掃描全文找出所有被明確提及、屬於「可能影響專案進度或合規的疑慮」的內容,列為 Risks——每一項風險要能對應到逐字稿裡具體的一段發言,不能是摘要者自己推論出來、逐字稿沒提到的風險。
5. 掃描全文找出明確指派或承諾的任務,每筆萃取 Owner(實際姓名)、Action(具體動詞+受詞)、Due Date(依②換算成 YYYY-MM-DD,未提到則標記「未訂」)、Priority(無語氣線索一律 Medium)。
6. 依 ④ 的格式整理輸出。

## ④ 輸出格式
使用以下 Markdown 結構輸出,四個區塊都要有,即使某區塊內容是「無」也要明確寫出「無」而不是省略整個區塊:

```markdown
## Meeting Summary
<一段 3-4 句話的專案進度摘要>

## Decisions
1. <決議事項一>
2. <決議事項二>
...

## Risks
- <風險項目一>
- <風險項目二>
...

## Action Items
| Owner | Action | Due Date | Priority |
|---|---|---|---|
| <姓名> | <具體任務> | <YYYY-MM-DD 或「未訂」> | <High/Medium/Low> |
```

## ⑤ 品質自檢(產出後逐項確認,沒過就修再交)
- [ ] 摘要只包含逐字稿裡真實出現的資訊,沒有推論、沒有幻覺內容。
- [ ] Decisions 裡的每一項,都能在逐字稿找到對應的「明確拍板」語句(例如「我們決議…」「那就這樣定案」),不是單純的討論或提議。
- [ ] Risks 裡的每一項,都能在逐字稿找到對應的具體發言,且用詞精簡(2-4 個字的風險標籤,例如「Token Cost」「Data Residency」),不要整句話塞進去。
- [ ] 每一筆 Action Item 的 Owner 是逐字稿裡實際出現的姓名,Action 是具體動作;相對日期已依會議日期換算,未提到期限則標記「未訂」。
- [ ] 人名保留逐字稿原文寫法,沒有自己代換或猜測身分。
- [ ] 四個區塊都存在,內容為空時明確寫「無」。
