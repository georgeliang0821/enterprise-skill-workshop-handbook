# M6 收割:把今天的事故變成規則與版本

> **重構版定位變更**:M6 從「講解+討論」改為**動手收割**。今天全天有四次親身經歷的事故(M2a 漂移、M3c 誤觸發、M4 覆蓋、M5 寫入事故),每一次都已經自然長出「新規則 + 版本異動」——M6 要做的是把這件事**制度化**:填收割表、寫 CHANGELOG、判斷版本號。假設性案例降級為課後補充。

## 資料夾內容

| 檔案 | 用途 |

## 課堂流程(30 分鐘)

1. **(5 分)講師定調**:今天四次事故你們都當場修掉了——但「修掉」跟「團隊資產」差一步:沒有紀錄,三個月後沒人知道為什麼有這條規則、也沒人敢動它。
2. **(15 分)填收割表**:打開 `incident-harvest-worksheet.md`,把自己今天的四次事故填進去。M4 那列已示範(它今天真的從 0.1.0 → 0.2.0)。
3. **(8 分)轉寫 CHANGELOG**:挑兩個 Skill(建議 `openapi-to-fastapi-scaffold` 跟 `action-item-to-jira`),把對應列轉成正式 CHANGELOG 條目。
4. **(2 分)收**:`.agent.md` 也是要治理的資產(見講義);「寫入型 Skill 上線前要不要有人審」留到 M7 的 INDEX gate 一起處理。

## 版本號規則(SemVer 套用在 Skill 上)

| 版本異動 | 什麼情況 | 今天的實例 |
|---|---|---|
| Patch(0.0.x) | 措辭調整,不影響邏輯或輸出結構 | M3c 改 description 對比句 |
| Minor(0.x.0) | 新增品質規則、新增輸入欄位、輸出新增區塊(舊的仍相容) | M4 重跑保護(0.1.0→0.2.0)、M5 去重規則 |
| Major(x.0.0) | 既有輸出結構被改變或欄位被移除,下游需要跟著調整 | (今天沒發生;例:Decisions 改成物件結構,Portal parser 要跟著改) |
